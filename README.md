# English Coach

Telegram-бот и Mini App для английского, который превращает личные ошибки в практику. Next.js + MongoDB, npm.

## Реализовано (P0)

- Telegram Mini App authentication: проверка initData на сервере, httpOnly session cookie.
- Onboarding: язык, уровень, цель, интересы, ежедневная цель, часовой пояс.
- Текстовый разговор в боте и Web App; structured AI corrections; отдельная natural version.
- Банк ошибок с повторяемостью, категориями, объяснениями и освоением.
- Упражнения на личных ошибках и словах; проверка сервером; интервалы 0 / 1 / 3 / 7 / 14 / 30 дней.
- Сохранение слов из разговоров, dashboard, прогресс, XP и streak.
- Адаптивная навигация, загрузка, пустые состояния и ошибки запросов.

## Структура и запуск

Один репозиторий, три npm workspaces:

- `apps/web` — Next.js, Mini App, веб-авторизация и API; деплой на Vercel.
- `apps/bot` — самостоятельный Node.js HTTP-сервер Telegram; деплой на Railway.
- `packages/core` — общие MongoDB, AI, пользователи, лимиты и учебная логика.

Бот и веб используют одну MongoDB. Веб обращается к собственному `/api`, бот — непосредственно к общей логике и базе. Cookies остаются на домене веб-приложения.

Требования: Node.js 22.9+, npm, MongoDB Atlas или replica set. Для production выбран Node.js 22. Standalone MongoDB не поддерживает используемые транзакции.

1. Выполнить `npm ci` из корня репозитория.
2. Если `.env.local` ещё нет, скопировать `.env.example` в `.env.local`. Существующий файл не перезаписывать.
3. Заполнить MongoDB, Telegram, AI и `SESSION_SECRET` (случайная строка от 32 символов).
4. `APP_URL` — публичный HTTPS-адрес веб-приложения. `TELEGRAM_WEBHOOK_URL` — отдельный HTTPS-адрес бота с путём `/telegram/webhook`.
5. Один раз создать индексы: `npm run db:indexes`.
6. Самостоятельно запустить веб: `npm run dev`; в другом терминале бот: `npm run dev:bot`. Команды читают общий `.env.local` из корня. Веб по умолчанию слушает порт 3000, бот — 3001 (или `PORT`). При прямом запуске workspace переменные нужно передать отдельно.
7. Для локальной работы Telegram нужны два HTTPS-туннеля: к вебу и боту. Их адреса указать в переменных выше.
8. Когда оба HTTPS-адреса доступны, выполнить `npm run telegram:setup`. Команда регистрирует webhook, меню и команды; автоматически при установке или запуске не выполняется. У одного Telegram-бота один webhook: для локальной разработки лучше отдельный бот, чтобы не переключать production.
9. Открыть `/start` в боте → «Открыть English Coach» → заполнить профиль.

Production: [пошаговый деплой на Vercel и Railway](docs/DEPLOYMENT.md). Веб собирается командой `npm run build`, запускается через `npm start`. Бот запускается через `npm run start:bot`, отдельная компиляция ему не нужна: TypeScript выполняется через `tsx`, который включён в production-зависимости. Production-команды используют окружение хостинга, не загружают корневой `.env.local` автоматически.

Без сервисных ключей приложение не подменяет AI фиктивными ответами. Вход из обычного браузера начинается с перехода в Telegram; отдельный Telegram Login Widget не включён в P0.

## Проверка вручную

1. Войти через Telegram и заполнить профиль; убедиться, что данные сохраняются.
2. Написать `Yesterday I go to shop` в Mini App и боте. Проверить исправления и банк ошибок.
3. Добавить предложенное слово кнопкой `+`; повторное добавление не создаёт дубль.
4. Открыть практику, ответить правильно и с ошибкой; проверить XP, mastery, дату повторения.
5. Повторить отправку того же requestId / exercise ID — повторной награды быть не должно.
6. Проверить данные со вторым Telegram-аккаунтом: они изолированы.
7. Проверить неподписанный / просроченный initData, чужой Origin, неверный webhook secret.
8. Отключить AI / базу: интерфейс сохраняет введённый текст и показывает ошибку.
9. Проверить мобильный экран, клавиатурную навигацию и длинные предложения.

Сборка, запуск проекта и tsc агентом не выполнялись по инструкции пользователя. Статический аудит интерфейса — `docs/premium-audit.json`; он не заменяет функциональную проверку.
