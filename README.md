# English Coach

Telegram-бот и Mini App для английского, который превращает личные ошибки в практику. Next.js + MongoDB, npm.

## Реализовано (P0)

- Telegram Mini App authentication: проверка initData на сервере, httpOnly session cookie.
- Onboarding: язык, уровень, цель, интересы, ежедневная цель, часовой пояс.
- Голосовые ответы в боте с кнопкой `text`, текстовый разговор в Web App; structured AI corrections; отдельная natural version.
- Банк ошибок с повторяемостью, категориями, объяснениями и освоением.
- Упражнения на личных ошибках и словах; проверка сервером; интервалы 0 / 1 / 3 / 7 / 14 / 30 дней.
- Сохранение слов из разговоров, dashboard, прогресс, XP и streak.
- Адаптивная навигация, загрузка, пустые состояния и ошибки запросов.

## Структура и запуск

Один репозиторий, три npm workspaces:

- `apps/web` — Next.js, Mini App, веб-авторизация и API; деплой на Vercel.
- `apps/bot` — самостоятельный Node.js-бот с long polling; деплой на Railway.
- `packages/core` — общие MongoDB, AI, пользователи, лимиты и учебная логика.

Бот и веб используют одну MongoDB. Веб обращается к собственному `/api`, бот — непосредственно к общей логике и базе. Cookies остаются на домене веб-приложения.

Требования: Node.js 22.9+, npm, MongoDB Atlas или replica set. Для production выбран Node.js 22. Standalone MongoDB не поддерживает используемые транзакции.

1. Выполнить `npm ci` из корня репозитория.
2. Если `.env.local` ещё нет, скопировать `.env.example` в `.env.local`. Существующий файл не перезаписывать.
3. Заполнить MongoDB, Telegram, AI и `SESSION_SECRET` (случайная строка от 32 символов).
4. `APP_URL` — публичный HTTPS-адрес веб-приложения. Бот сам получает сообщения через Telegram `getUpdates`; адрес и секрет webhook не нужны.
5. Один раз создать индексы: `npm run db:indexes`.
6. Самостоятельно запустить веб: `npm run dev`; в другом терминале бот: `npm run dev:bot`. Веб читает корневые `.env` и `.env.local`. Бот также поддерживает `apps/bot/.env` и `apps/bot/.env.local`, в том числе при запуске непосредственно из `apps/bot` через `npm start` или `npm run dev`. Приоритет для бота: переменные процесса → `apps/bot/.env.local` → `apps/bot/.env` → корневой `.env.local` → корневой `.env`. Веб по умолчанию слушает порт 3000, бот — 3001 (или `PORT`).
7. Бот не требует HTTPS-туннеля или публичного домена. Для открытия локального Mini App нужен HTTPS-туннель только к вебу; можно оставить `APP_URL` адресом уже развёрнутого Vercel-приложения.
8. Для настройки кнопки меню и списка команд выполнить `npm run telegram:setup`. Получение сообщений не зависит от этой команды: при запуске бот сам удаляет старый webhook без сброса очереди и начинает long polling. Запускать только один процесс на токен; для параллельной локальной разработки использовать отдельного бота.
9. Открыть `/start` в боте → «Открыть English Coach» → заполнить профиль.

Railway использует Railpack: зависимости устанавливаются автоматически, затем выполняется `npm run start:bot`. Dockerfile и локальный Docker не нужны.

Production: [пошаговый деплой на Vercel и Railway](docs/DEPLOYMENT.md). Веб собирается командой `npm run build`, запускается через `npm start`. Бот запускается через `npm run start:bot`, отдельная компиляция ему не нужна: TypeScript выполняется через `tsx`, который включён в production-зависимости. Бот загружает доступные env-файлы и при обычном запуске; переменные хостинга имеют приоритет. Файлы с ключами остаются исключёнными из Git.

Без сервисных ключей приложение не подменяет AI фиктивными ответами. Вход из обычного браузера начинается с перехода в Telegram; отдельный Telegram Login Widget не включён в P0.

Главная `/` в обычном браузере сразу показывает мобильный лендинг с преимуществами и кнопкой перехода в бота, в том числе при сохранённой сессии. Ссылки на главной и экране входа ведут в `@engmova_bot`; адрес задан в `apps/web/src/lib/telegram-bot.ts`. При запуске из Telegram Mini App главная открывает учебный кабинет с обычной серверной проверкой авторизации.

Административные уведомления отправляются отдельным ботом из `ADMIN_NOTIFICATION_BOT_TOKEN` только пользователям из `ADMIN_TELEGRAM_IDS` (ID через запятую, пробел или точку с запятой). Указать обе переменные на вебе и в боте; каждый администратор должен предварительно открыть бот уведомлений и нажать Start. Сообщения содержат `Project: EngBot`: посещение лендинга или кабинета, открытие профиля, прокрутка до низа лендинга один раз за открытие, `/start`, первое успешное завершение опроса в боте и входящие сообщения (включая текст). Анонимные посещения содержат ID посещения, события авторизованных пользователей — имя и Telegram ID. Повторные Telegram updates и клиентские события с тем же ID не дублируют отправку. Доставка выполняется без гарантированного фонового повторения при сетевой ошибке и не прерывает основное действие пользователя. Для очистки истории уведомлений через 30 дней и счётчиков ограничения частоты выполнить `npm run db:indexes`.

## Проверка вручную

### Кредиты и Telegram Stars

- Вместо продажи доступа на 7/30 дней используются пакеты: **100 Stars → 1000 кредитов, 250 → 2500, 500 → 5000**. Покупка разовая, кредиты не сгорают. Общие цены находятся в `packages/core/src/pricing.ts`.
- Один текстовый ответ с исправлениями или новая тема стоит **5 кредитов**, упражнение с одной проверкой — **10 кредитов**. Входящий голос добавляет **10 кредитов/мин**, исходящий — **50 кредитов/мин**. Длительность округляется до начатой секунды, не минуты. 30 секунд пользователя + текстовый ответ = 10 кредитов; дополнительно 30 секунд голоса бота = всего 35.
- `/balance` показывает баланс и пакеты; `/text` включает экономный режим, `/settings` → **Bot speaking** (или `/speaking`) меняет формат ответа по умолчанию: текст или голос. Та же настройка доступна в профиле Mini App. Под текстом кнопок нет; под голосом — **Show text · free**, бесплатно показывающая сохранённый текст без запроса к AI. Для новой озвучки резервируются до 50 кредитов; после доставки возвращается разница. Лимит одной озвучки — 60 секунд; повтор готовой записи бесплатный.
- На аккаунт один раз начисляются **100 приветственных кредитов**, в том числе при переходе существующего аккаунта. Инициализация кошелька происходит автоматически при первом обращении. XP остаётся отдельным показателем прогресса. Покупки и кредиты общие для бота и Mini App.
- Ранее оплаченный доступ сохраняется до `premiumUntil` и не расходует кредиты. Старые кнопки `/premium` открывают кредиты; новые оплаты старых счетов отклоняются на pre-checkout. Уже оплаченные старые счета, доставленные с задержкой, обрабатываются по прежним условиям.
- Баланс резервируется до платной операции. Успех и учебные данные сохраняются транзакционно, ошибки освобождают резерв. Уникальные request/charge ID защищают от повторных списаний и начислений. Зависшие резервы возвращаются при следующем обращении через пять минут. Текстовый результат сохраняется в истории Mini App до Telegram-доставки; временная ошибка Telegram не создаёт нового списания.
- `refunded_payment` снимает начисленные за покупку кредиты один раз. Уже потраченная возвращённая покупка может сделать баланс отрицательным; пополнение сначала покрывает долг. История кошелька доступна только владельцу в `/api/me`; публичная администрация не получает записи кошелька или AI usage.
- Бот не списывает кредиты за автоматические напоминания: они статические и текстовые. Лимит 100 AI-запросов в сутки сохранён как защита; прежние 15 минут голоса в день применяются только к действующему старому доступу.
- `/paysupport <описание и ID квитанции>` использует существующие административные уведомления: настройте `ADMIN_NOTIFICATION_BOT_TOKEN` и `ADMIN_TELEGRAM_IDS`. Provider token для Stars не нужен.
- После деплоя обновите меню через `npm run telegram:setup`, индексы — через `npm run db:indexes`. Эти команды изменяют Telegram/MongoDB; агент их не запускал.

Сценарии проверки платежей, гонок и сбоев: [docs/POINTS.md](docs/POINTS.md). Для платёжных проверок используйте тестовую среду Telegram.

1. Войти через Telegram и заполнить профиль; убедиться, что данные сохраняются.
2. Написать `Yesterday I go to shop` в Mini App и боте. Проверить исправления и банк ошибок.
3. Добавить предложенное слово кнопкой `+`; повторное добавление не создаёт дубль.
4. Открыть практику, ответить правильно и с ошибкой; проверить XP, mastery, дату повторения.
5. Повторить отправку того же requestId / exercise ID — повторной награды быть не должно.
6. Проверить данные со вторым Telegram-аккаунтом: они изолированы.
7. Проверить неподписанный / просроченный initData, чужой Origin и корректную обработку повторных сообщений.
8. Отключить AI / базу: интерфейс сохраняет введённый текст и показывает ошибку.
9. Проверить мобильный экран, клавиатурную навигацию и длинные предложения.
10. Открыть `/` в обычном браузере, также с сохранённой сессией: должен быть лендинг. Проверить кнопку перехода в бота на телефоне, затем открыть главную из Mini App и перейти на неё из другого раздела: должен быть учебный кабинет.

Сборка, запуск проекта и tsc агентом не выполнялись по инструкции пользователя. Статический аудит интерфейса — `docs/premium-audit.json`; он не заменяет функциональную проверку.

### Conversations in Telegram

Бот отправляет ответы в диалоге и новые темы голосовыми сообщениями. Кнопка `text` под голосовым отправляет текстовую версию с исправлениями в ответ на исходное сообщение, без нового AI-запроса и расходования лимита. Настройки, оплата и служебные сообщения остаются текстовыми.

После настройки профиля пользователь может отправлять текст или голосовые до 3 минут и 10 МБ. Голос распознаётся и передаётся в обычный диалог с исправлениями; расшифровка сохраняется для повторной обработки. Распознавание и ответ используют один слот общего лимита сообщений. При ошибке бот предлагает повторить запись или написать текст. Настройка профиля по-прежнему использует кнопки и текстовые поля.

Распознавание использует существующий `OPENAI_API_KEY` и `STT_MODEL` (по умолчанию `gpt-4o-mini-transcribe`), согласно [OpenAI Transcriptions API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create). Оценка произношения не выполняется: исправления строятся по распознанному тексту.

Озвучивание использует существующий `OPENAI_API_KEY` и Speech API: `TTS_MODEL` (по умолчанию `gpt-4o-mini-tts`), `TTS_VOICE` (по умолчанию `coral`). При сбое синтеза бот отправляет текст. Тексты сохраняются в MongoDB `voiceReplies`, аудио — в Telegram; новые индексы не нужны. Технические контракты: [OpenAI Speech API](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create), [Telegram sendVoice](https://core.telegram.org/bots/api#sendvoice).

`/start` configures the learner profile with inline buttons. `/settings` opens Bot speaking and Profile and reminders; the latter edits the full profile. After setup the coach asks the first question. `/topic` starts a fresh conversation; `/pause` and `/resume` control daily topics. Users choose a timezone and 09:00, 13:00 or 19:00, or disable daily topics. Existing web users can run `/start` to configure this in the bot.

The bot process runs the daily scheduler alongside polling; it must stay online. Topics are sent during the selected local hour only, after at least an hour without user interaction. They use interests, level and recent conversation history. No extra cron service is needed. MongoDB stores drafts, scheduling state and separate conversation starters; these starters do not affect learning statistics. Daily delivery prioritizes avoiding duplicate nudges: an ambiguous send timeout skips that date instead of retrying blindly.

After deployment, `npm run telegram:setup` refreshes the Telegram command menu and `npm run db:indexes` creates the added history/scheduler indexes.

### Страница администрирования `/uzerz`

Страница `/uzerz` доступна всем без авторизации и настройки Telegram ID. Она показывает пользователей с датами регистрации и настройками, сообщения, ошибки, словарь, упражнения, активность, платежи и сообщения бота. Есть поиск, порядок по дате и серверная пагинация; служебные коллекции представлены счётчиками. Изменение и удаление записей не предусмотрены.

### Логирование действий

События бота и web сохраняются в MongoDB `eventLogs` и доступны на `/uzerz` → **Event logs**; последний шаг онбординга — в таблице **Users**. Полный список событий, точек подключения и инструкции отключения: [docs/LOGGING.md](docs/LOGGING.md). Общий выключатель новых логов: `EVENT_LOGGING_ENABLED=false` на web и боте.
