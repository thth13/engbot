# Логирование действий

Логирование добавлено для `/start` бота, онбординга, открытия сайта/Web App и нажатий на web-кнопки. Данные сохраняются в MongoDB, отдельно от Telegram-уведомлений администраторам.

## Где смотреть

- Коллекция `eventLogs`: история событий с серверным `createdAt` в UTC.
- `users.onboardingProgress.bot` и `users.onboardingProgress.web`: последний сохранённый прогресс пользователя.
- `/uzerz` → **Event logs**: просмотр истории, поиск по событию, Telegram ID, странице, названию кнопки или Visitor ID.
- `/uzerz` → **Users** → **Bot onboarding progress** / **Web onboarding progress**: состояние онбординга.

`/uzerz` остаётся публичной, как было запрошено ранее: журнал и сведения о прогрессе также доступны без авторизации.

## Какие события записываются

| Событие                    | Когда                                                                                                              | Место записи                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `bot_start`                | Пользователь отправил `/start`, включая `/start` с параметром                                                      | `apps/bot/src/telegram.ts`, обработчик Telegram update                                                   |
| `bot_onboarding_step`      | Начало настройки бота и каждый успешный переход вперёд/назад                                                       | `apps/bot/src/onboarding.ts`, `beginOnboarding` и `advanceOnboarding`                                    |
| `bot_onboarding_completed` | Все ответы валидны и настройки бота сохранены                                                                      | `apps/bot/src/onboarding.ts`, финальный checkpoint                                                       |
| `web_app_open`             | Загрузился документ сайта: landing или Web App; открытие `/uzerz` исключено                                        | `apps/web/src/components/web-event-logger.tsx`, подключён из `apps/web/src/app/layout.tsx`               |
| `web_app_authenticated`    | Web App получил подтверждённую пользовательскую сессию                                                             | `apps/web/src/components/coach-app.tsx`, эффект по `authenticatedUserId`                                 |
| `web_button_click`         | Нажатие на доступную кнопку, ссылку, элемент с `role=button` / `role=option`, `summary`, submit/button/reset input | `apps/web/src/components/web-event-logger.tsx`, общий capture-обработчик `document.click`                |
| `web_onboarding_step`      | Показан текущий вопрос вступительного web-онбординга, включая Back                                                 | `apps/web/src/components/coach-app.tsx`, `Profile`; сохранение в `apps/web/src/lib/web-event-logging.ts` |
| `web_onboarding_completed` | Первый профиль успешно провалидирован и сохранён на сервере                                                        | `apps/web/src/app/api/[...path]/route.ts`, ветка `profile`                                               |

`bot_start` означает команду пользователя, а не запуск серверного процесса. Перезапуск процесса по-прежнему виден в существующих консольных сообщениях `server.ts` / `polling.ts`.

У событий бота `initial: true` обозначает первую настройку бота (ещё не сохранён `bot.hour`); повторные `/settings` / перезапуски настройки тоже логируются с `initial: false` после первого завершения. Web-событие завершения записывается только при первом сохранении профиля, не при обычном редактировании.

## Как определяется шаг, на котором остановились

В каждом `users.onboardingProgress.bot/web` сохраняются:

- `status`: `in_progress` или `completed`;
- `step`: текущий вопрос, нумерация с **1**;
- `stepName`: техническое имя вопроса; после завершения — `completed`;
- `maxStep`: максимальный достигнутый номер вопроса в текущем прохождении;
- `totalSteps`: число вопросов;
- `updatedAt`: время последнего перехода;
- `completedAt`: время успешного завершения, если оно состоялось.

Если `status = in_progress`, поле `step` — последний открытый вопрос, на котором пользователь остался. Переход Back уменьшает `step`, сохраняя `maxStep`. Закрытие окна или молчание в Telegram не даёт достоверного события выхода: отдельный выдуманный статус «бросил» и время выхода не записываются. Прогресс не стирается при закрытии клиента.

Бот: 4 вопроса — `nativeLanguage`, `goal`, `replyMode`, `hour`. Часовой пояс — `Asia/Kolkata`. События переходов и прогресс коммитятся в существующей транзакции вместе с ответами и checkpoint; если транзакция не завершилась, переход не считается сохранённым. Внутренний `bot.draft.step` остаётся с нумерацией от 0 и продолжает управлять работой онбординга.

Web: 4 вопроса — `nativeLanguage`, `goal`, `replyMode`, `schedule` (время в `Asia/Kolkata`). Прогресс сохраняется отдельно от ответов формы. Поздно пришедший запрос старого шага не перезаписывает более новый прогресс или завершённый профиль. Это журнал последнего достигнутого вопроса, а не автоматическое восстановление формы после закрытия браузера.

## Поля события и границы сбора

Каждое событие содержит `_id`, `event`, `source`, `createdAt`. Когда доступны, сохраняются `userId`, `visitorId`, `visitId`, `path` и `details`.

- `userId` в web берётся только из проверенной серверной сессии, не из тела запроса.
- Для анонимного визита есть `visitorId` из sessionStorage. Если storage недоступен, он живёт в памяти документа. Событие открытия до авторизации можно связать с последующей авторизацией по `visitorId` / `visitId`.
- `visitId` объединяет события одной загруженной страницы; SPA-переходы не создают новое открытие, полная перезагрузка создаёт.
- У web-событий `details.occurredAt` — клиентское время. `createdAt` — время записи сервером. Клиентское время может отличаться, события клиента не являются доказательством бизнес-операции.
- Для кнопки сохраняются название и pathname целевой ссылки, без query/hash. Имя определяется по `data-log-id`, `id`, `aria-label`, `title`, видимому тексту, затем типу контрола. Чтобы дать постоянное имя конкретной кнопке, добавьте `data-log-id="save-profile"`.
- Значения полей ввода, ответы формы, initData, cookies и токены этот механизм не собирает. Видимые подписи кнопок могут содержать данные, показанные самим интерфейсом.
- Capture-обработчик покрывает динамические кнопки и клавиатурную активацию, вызывающую click. Недоступные кнопки пропускаются. Внутренние кнопки OS-попапов нативных select/date picker и интерфейс Telegram вне страницы не являются DOM-кнопками сайта и не собираются.
- Web-доставка использует `fetch(..., keepalive: true)`, не задерживает действия и не показывает ошибки пользователю. При отсутствии сети, блокировщике, закрытии процесса или ограничении запросов событие может потеряться; долговременной клиентской очереди и автоматических повторов нет.

| Файл                                           | Назначение                                                            |
| ---------------------------------------------- | --------------------------------------------------------------------- |
| `packages/core/src/events.ts`                  | Общие `logEvent` и `eventLoggingEnabled`, защита от дублей по `_id`   |
| `packages/core/src/db.ts`                      | Коллекции `events` → `eventLogs`, `eventLimits` → `eventLogLimits`    |
| `packages/core/src/schema.ts`                  | Типы `EventLog`, `OnboardingProgress`, поле пользователя              |
| `packages/core/package.json`                   | Экспорт `@engbot/core/events`                                         |
| `apps/web/src/lib/telemetry.ts`                | Отправка web-событий на POST `/api/telemetry`                         |
| `apps/web/src/lib/track-event.ts`              | Общий `currentVisitorId`, также используется прежними уведомлениями   |
| `apps/web/src/lib/web-event-logging.ts`        | Валидация, привязка сессии, лимит, сохранение web-прогресса и событий |
| `apps/web/src/app/api/[...path]/route.ts`      | Ветка `telemetry` и фиксация завершения web-онбординга                |
| `apps/web/src/components/web-event-logger.tsx` | Открытие документа и все web-кнопки одним обработчиком                |
| `apps/web/src/app/layout.tsx`                  | Подключение `<WebEventLogger />`                                      |
| `apps/web/src/components/coach-app.tsx`        | Авторизация Web App и вопросы web-онбординга                          |
| `apps/bot/src/telegram.ts`                     | `/start`                                                              |
| `apps/bot/src/onboarding.ts`                   | Переходы и завершение онбординга бота                                 |
| `apps/web/src/lib/uzerz-schema.ts`             | Таблица Event logs и колонки прогресса Users                          |
| `scripts/mongo-indexes.mjs`                    | Индексы журнала и TTL служебного ограничителя                         |

POST `/api/telemetry` использует существующую проверку Origin. Лимит — 240 событий в минуту на пользователя или хеш адреса источника для анонимных посетителей. Сырой IP в новых коллекциях не сохраняется. Служебные записи `eventLogLimits` истекают через час при установленном TTL-индексе; для `eventLogs` автоматическое удаление не настроено. Индексы добавлены в скрипт, но команда создания индексов не запускалась.

## Как отключить или удалить

1. Самое простое: выставить `EVENT_LOGGING_ENABLED=false` **на web и боте** и перезапустить соответствующие сервисы. Это отключит новые записи в `eventLogs`, лимиты и аналитические поля прогресса. Запросы браузера останутся, но сервер сразу ответит без записи. Уже накопленные данные останутся в MongoDB.
2. Чтобы прекратить общие web-запросы, уберите `<WebEventLogger />` и импорт из `apps/web/src/app/layout.tsx`. Это отключит открытия и кнопки на всём сайте.
3. Чтобы отключить отдельные web-события, уберите соответствующие вызовы `trackWebEvent(...)` из `coach-app.tsx` или `web-event-logger.tsx`. При удалении эффекта также удалите связанный `useRef`, если он больше не используется.
4. Чтобы отключить только сохранение web-онбординга, уберите ветку `web_onboarding_step` в `web-event-logging.ts` и блок `LOGGING` в ветке `profile` API. Валидацию и сохранение обычных `settings` оставьте.
5. Чтобы отключить только бот, удалите вызов `logEvent` в `telegram.ts` и блоки `if (eventLoggingEnabled())` / `if (result.modifiedCount && eventLoggingEnabled())` в `onboarding.ts`. Не удаляйте существующие `bot.draft`, `checkpoint`, `db.updates` и сохранение настроек — они нужны самому боту.
6. Для полного удаления механизма затем можно убрать endpoint `telemetry`, новые служебные файлы/экспорт/типы/коллекции/индексы и поля в описании таблиц `/uzerz`. Данные в базе удаляются отдельно по вашему решению.

Места подключения помечены комментарием `LOGGING`; также удобно искать `trackWebEvent`, `logEvent`, `eventLoggingEnabled`, `onboardingProgress`.

## Уже существовавшие уведомления

До этой задачи уже работали `notifyAdmins` в `packages/core/src/notifications.ts`, `/api/events`, `trackEvent` в `apps/web/src/lib/track-event.ts`, уведомления о `/start`, сообщениях боту и завершении бот-онбординга. Они продолжают работать независимо и используют `ADMIN_NOTIFICATION_BOT_TOKEN` / `ADMIN_TELEGRAM_IDS`. `EVENT_LOGGING_ENABLED=false` их не отключает. Если нужно убрать и уведомления, очистите `ADMIN_NOTIFICATION_BOT_TOKEN` на нужном сервисе либо удалите соответствующие вызовы `notifyAdmins` / `trackEvent`.

Открытие `/uzerz` не отправляет и не сохраняет `web_app_open`: исключение установлено в `apps/web/src/lib/telemetry.ts` и `apps/web/src/lib/web-event-logging.ts`. Нажатия кнопок этой страницы по-прежнему логируются. Уже сохранённые события открытия не удаляются.
